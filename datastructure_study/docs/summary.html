BIRD Text-to-SQL: fixing failures with structured generation

Task: turn an English question + a database into a SQL query. A query is "correct" (EX) if running it returns exactly the gold result. Test slice: first 340 dev questions.

1. The problem we found in the baseline

The baseline model writes SQL as free text and scores EX = 48.2%. Looking at the 176 wrong answers, the single biggest cause (34%) is over-selection: the logic is right, but the model puts extra columns in the SELECT, so the result set doesn't match gold.

Example — "list the magnet schools with over 500 SAT takers":

gold:     SELECT School ...                              (1 column)
baseline: SELECT CDSCode, School, District, County, ...  (5 columns) → marked wrong

This cannot be fixed reliably by prompting — the model just needs to be structurally prevented from adding columns.

2. The idea: emit a structure, then compile it (M3)

Instead of letting the model write SQL text, we ask it to emit a small relational-algebra IR (JSON) where the projection is an explicit, minimal list. A deterministic compiler (ra_to_sql) turns that IR into SQL — and it can only output the columns listed, so over-selection becomes structurally impossible.

{ "from": "schools",
  "joins": [{"table":"satscores","on":["schools.CDSCode","satscores.cds"]}],
  "select": ["schools.School"],                 // <- minimal projection
  "where": "schools.Magnet = 1 AND satscores.NumTstTakr > 500" }

Baseline pipeline

question → model → free-form SQL text
model guesses columns, joins, projection

M3 pipeline

question → model → RA IR (JSON) → ra_to_sql → SQL
projection is explicit & minimal by construction

Why it's good: +9.71 EX, and the gain lands exactly on the over-selection bucket that prompting cannot fix (27 of 60 flipped). The example above now compiles to SELECT "schools"."School" ... → correct. 339/340 IRs parse and compile, so the "emit a structure" approach is reliable, and the prompt is schema-driven (works on any database).

The remaining 16 regressions: 13 are genuine model logic errors, 3 are minor compiler edge cases (e.g. a reserved-word table name). Net effect is still +33 queries.
