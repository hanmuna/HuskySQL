Compiled Minimal Projection for Text-to-SQL

Progress report · BIRD dev slice (questions 0–339) · July 24, 2026

1. Problem

GPT-5.2 writing SQL directly scores 48.24 EX on the slice. Dissecting its 176 failures, the largest class (34%) is over-selection: the SQL is semantically right but returns extra columns, and BIRD's exact-match scoring counts it as wrong.

2. Method

Instead of free-form SQL, the model fills a JSON relational-algebra form whose SELECT is an enumerated minimal list, and a ~120-line deterministic compiler turns it into SQL — columns outside the list cannot appear by construction. The API exposes no logits, so this post-hoc compiler stands in for constrained decoding.

3. Main result

EX rises from 48.24 to 57.94 (+9.71, p = 5×10⁻⁵), fixing 27 of the 60 over-selection failures — 72% of the zero-cost oracle upper bound computed before spending.

4. What carries the gain (ablations)

Format alone: keeping the JSON form but dropping the minimality rule gives +0.88, statistically nothing — the format is not the active ingredient.

Instruction alone: a single "select only the asked columns" prompt line gives +6.47, so soft prompting gets two-thirds of the way; the compiled version is still 3.2 points better and, unlike the instruction, guarantees that nothing slips past the declared list.

5. Does it transfer? (five models)

The identical protocol on five models, each against its own baseline: GPT-4.1-mini +12.35, GPT-5.2 +9.71, Claude Sonnet 4.5 +6.47 (best absolute, 61.18), DeepSeek-chat −3.53, Qwen3-Coder −2.94; all five obey the IR format (≥99% parse and compile).

Flip-level analysis explains the signs: net effect = in-bucket benefit − a model-specific "format tax" (semantic drift when forced into the IR); the two negative models pay 38–39 drift losses versus 12–28 for the positive ones. Two matched-strength pairs (Sonnet 54.7 vs Qwen 54.1; GPT-5.2 48.2 vs DeepSeek 48.8) flip sign despite equal baselines, ruling out the "no headroom" explanation. Practical rule: measure a model's failure profile first; apply the constraint only where the diagnosis indicates.

6. Boundary checks (zero-cost)

Deriving GROUP BY from functional dependencies would fix 0 of 143 remaining failures — the models' GROUP BY already matches their SELECT. Checking WHERE literals against the database would fix only 2 of 85 value errors — those errors are wrong choices, not invalid values. Both zeros confirm the principle's scope: a clause is compiler-fixable only if derivable from schema plus declared intent.

7. Statistics

All comparisons use exact McNemar tests; the method beats baseline decisively (p = 5×10⁻⁵), while the hard-vs-soft gap (+3.2) is not yet significant at 340 questions (p = 0.17).
